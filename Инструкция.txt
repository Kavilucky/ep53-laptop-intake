ЭКСПРЕСС-ДИАГНОСТИКА КОРПОРАТИВНЫХ НОУТБУКОВ ПРИ СКУПКЕ: N8N, POSTGRESQL, OLLAMA И TELEGRAM (DOCKER COMPOSE, CLOUDFLARE TUNNEL)
Эпизод 53. Канал: @ByteAutomate_AI

ЧТО ЭТО
Инженер вставляет загрузочную флешку в ноутбук продавца, скрипт за секунды снимает телеметрию (износ батареи, состояние SSD, серийники платы и системы, признаки корпоративной привязки) и отправляет на ваш сервер. PostgreSQL сверяет серийники со стоп-листом, код принимает решение (запрет, ручная проверка или лимит цены), локальная Ollama добавляет ограниченную уценку, Telegram-бот присылает карточку. Без абонентской платы за сервис: платите за сервер.

В АРХИВЕ
- docker-compose.yml: PostgreSQL 16, Ollama, n8n, cloudflared (Cloudflare Tunnel); тома pg_data, n8n_data, ollama_data, backups;
- .env.example: пример настроек (пароль базы, ключ шифрования n8n, домен, токен туннеля, чат приёмки, токен приёмки INTAKE_TOKEN, модель Ollama);
- init.sql: таблицы stop_list (стоп-лист серийников), price_rules (базовые цены по маске модели), devices (журнал приёмок с вердиктом и причинами);
- laptop_intake_n8n.json: сценарий n8n (21 узел; идентификаторы подключений пустые): вебхук приёмки, проверка токена, сверка со стоп-листом и ценой, решение, расчёт Ollama, запись в журнал, карточка в Telegram, ответ скрипту, ночная выгрузка журнала;
- collect_telemetry.py: скрипт для живой Linux-системы на флешке (только чтение; python3, dmidecode, smartctl; по желанию hivex для офлайн-реестра Windows);
- backup.sh: резервная копия базы оценок (дамп PostgreSQL и архив настроек);
- Инструкция.txt: этот файл.

ВАЖНО ДО ЗАПУСКА (честные ограничения)
1. Автор стек, сценарий, SQL-схему и скрипт на живом сервере и на реальных ноутбуках не запускал. Логика узлов Code (приём данных, решение, запрос и ответ Ollama) проверена в Node, а сбор батареи, SSD и серийников в скрипте проверен в Python на подставных данных; поиск следов в реестре Windows (hivexregedit) не проверялся вовсе. Теги образов (latest), узлы Telegram, Postgres, записи файла, HTTP-запросов и имена параметров сверьте в своих версиях. После первого успешного запуска закрепите версии образов.
2. Набор НЕ снимает и НЕ обходит блокировки MDM, Autopilot или прошивки. Он выявляет следы и помогает отказаться от сделки. Не покрыты: пароли BIOS и UEFI, персистентные модули вроде Absolute, облачные привязки, у которых нет следов на диске. Если Windows стёрта и раздела нет, офлайн-признаки не проверены, и ноутбук получает «ручную проверку», а не «чисто». Дополнительно запрашивайте у продавца подтверждение снятия устройства с MDM и проверяйте вход в BIOS вручную.
3. Серийники. Приёмщик вводит серийник с наклейки на корпусе; он сравнивается с серийником системы, прошитым в плату (SMBIOS, dmidecode system-serial-number). У некоторых производителей эти серийники по устройству не совпадают даже у исправной машины: проверьте правило сверки на своих моделях и при необходимости измените узел «Оценить сделку». Серийник платы (baseboard) записывается и проверяется по стоп-листу.
4. Цены и уценка. Базовые цены (price_rules) и коэффициенты износа в коде примерные: подберите свои. Ollama может добавить только 0-15% уценки поверх формулы, битый ответ даёт 0%; качество расчёта не проверялось. Решение о цене остаётся за человеком.
5. Вебхук открыт через Cloudflare Tunnel: защищён заголовком X-Radar-Token (INTAKE_TOKEN не короче 16 символов), входные данные очищаются, но ограничения числа запросов нет: добавьте правила Cloudflare. Редактор n8n закройте через Cloudflare Access. Условия бесплатного Cloudflare Tunnel проверяйте на сайте Cloudflare.
6. Юридическая сторона. Законность выкупа и происхождение техники, согласие продавца на диагностику, персональные данные на накопителях (152-ФЗ) и хранение серийников проверьте у юриста; набор не даёт юридических гарантий.
7. Убыток 145 000 ₽, время теста 5 секунд, цены и проценты износа в ролике иллюстративные параметры кейса и оценки владельца, не замеры.
8. Резервная копия базы оценок обязательна (см. чек-лист ниже).

ШАГ 1. СЕРВЕР
Нужен VPS с Linux, Docker и Docker Compose. Аренда: Timeweb Cloud по партнёрской ссылке https://timeweb.cloud/r/nf413716
ПОМЕТКА О ВОЗНАГРАЖДЕНИИ: ссылка партнёрская, автор канала получает вознаграждение, цена для вас от этого не растёт. Тарифы (по данным автора на момент записи от ~490 ₽ в месяц, не проверено) и бонус проверяйте на сайте.

ШАГ 2. ТУННЕЛЬ И БОТ
Создайте туннель в Cloudflare Zero Trust, маршрут вашего домена на http://n8n:5678, токен впишите в TUNNEL_TOKEN. В Telegram создайте бота у @BotFather (токен вносится в учётные данные Telegram в n8n). Чат приёмки и его chat_id впишите в ADMIN_CHAT_ID.

ШАГ 3. НАСТРОЙКИ
Скопируйте файлы на сервер, например в /opt/laptop-intake. В папке:
  cp .env.example .env
  openssl rand -hex 32     (выполните трижды: POSTGRES_PASSWORD, N8N_ENCRYPTION_KEY, INTAKE_TOKEN)
Впишите значения и домен HOST. N8N_ENCRYPTION_KEY задайте один раз и никогда не меняйте.

ШАГ 4. ЗАПУСК
  docker compose up -d
  docker compose ps
  docker compose exec ollama ollama pull <модель из OLLAMA_MODEL>
Должны работать postgres, ollama, n8n и cloudflared. Если контейнер не стартует, смотрите docker compose logs. Откройте редактор n8n и создайте администратора.

ШАГ 5. ЦЕНЫ И СТОП-ЛИСТ
Замените примеры в price_rules и stop_list своими:
  docker compose exec postgres psql -U $POSTGRES_USER -d $POSTGRES_DB -c "INSERT INTO price_rules (model_pattern, base_price) VALUES ('МАСКА_МОДЕЛИ%', 25000);"
  docker compose exec postgres psql -U $POSTGRES_USER -d $POSTGRES_DB -c "INSERT INTO stop_list (serial, reason) VALUES ('СЕРИЙНИК', 'причина');"

ШАГ 6. СЦЕНАРИЙ
В n8n: Workflows, Import from file, laptop_intake_n8n.json. Создайте учётные данные Telegram (токен бота) и PostgreSQL (хост postgres, база и пользователь из .env) и выберите их в узлах. Активируйте сценарий. Адрес вебхука: https://ВАШ_ДОМЕН/webhook/laptop-intake.

ШАГ 7. ФЛЕШКА
Запишите на флешку живую Linux-систему (дистрибутив выберите сами) и положите collect_telemetry.py. На ноутбуке продавца с его согласия загрузитесь с флешки. Системный раздел Windows, если он есть, смонтируйте только для чтения (mount -o ro). Запуск (сначала без отправки):
  sudo python3 collect_telemetry.py --sticker СЕРИЙНИК_С_НАКЛЕЙКИ --dry-run
Затем с отправкой на сервер:
  sudo python3 collect_telemetry.py --sticker СЕРИЙНИК_С_НАКЛЕЙКИ --url https://ВАШ_ДОМЕН/webhook/laptop-intake --token ВАШ_INTAKE_TOKEN

ШАГ 8. ПРОВЕРКА
Проверьте на своих ноутбуках: ноутбук без следов и со стёртым диском (должна быть ручная проверка), ноутбук с серийником из стоп-листа (запрет), ноутбук с несовпавшей наклейкой (запрет), ноутбук с корпоративным профилем (запрет, если следы остались в реестре). Сверьте износ батареи и SSD с другими утилитами.

РЕЗЕРВНАЯ КОПИЯ (ЧЕК-ЛИСТ, правило 3-2-1)
[ ] запустить bash backup.sh: дамп PostgreSQL базы оценок и архив настроек;
[ ] 3 копии, 2 разных носителя, 1 вне сервера; архивы с .env хранить закрыто;
[ ] ночная выгрузка журнала приёмок в том backups работает, но она не заменяет полную копию;
[ ] не удалять оригиналы, пока копия не проверена;
[ ] восстановить копию на тестовой машине и открыть журнал приёмок, стоп-лист и цены.
